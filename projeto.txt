1. Stack de Interface Gráfica (GUI)

PyQt6 ou PySide6 (Recomendado): É a melhor opção para esse projeto. Oferece o componente QTextEdit (que possui suporte nativo a Markdown, navegação de cursor rápida e suporte a temas) e o QSplitter, que permite criar a barra lateral retrátil dividindo a tela de forma fluida. O resultado visual fica idêntico a um aplicativo nativo desktop.

2. Estrutura de Arquivos e Armazenamento do Projeto

Para manter a filosofia de "arquivo simples", o TramaPad pode salvar o projeto do escritor de duas formas:

Opção A — Arquivo Único .trama (JSON compacto): O arquivo .trama é apenas um JSON renomeado que guarda todo o projeto em um só lugar.
Opção B — Pasta do Projeto (Textos + JSON): Salva os capítulos como arquivos .txt ou .md comuns em uma pasta invisível e usa um arquivo de metadados para as fichas de personagens.

3. Bibliotecas Auxiliares Recomendadas

watchdog: Para detectar alterações nos arquivos e garantir salvamento automático em segundo plano sem travar a interface.

python-docx: Para exportar os capítulos compilados diretamente em formato .docx (Microsoft Word) quando o escritor terminar.

PyInstaller ou Nuitka: Para empacotar todo o código Python em um executável único (.exe para Windows, .dmg para macOS ou executável para Linux) sem que o usuário final precise ter o Python instalado.

Acho que podemos estruturar o **TramaPad** com uma filosofia bastante clara:

> **A simplicidade de um bloco de notas, mas com a estrutura necessária para escrever uma obra inteira.**

A referência não seria "um Word simplificado", mas **um editor de texto que sabe que o texto pertence a um projeto literário**.

# 2. Estrutura principal

Eu dividiria o TramaPad em apenas **quatro áreas conceituais**:

### Escrita

O editor propriamente dito.

### Projeto

Capítulos, estrutura da obra e metadados.

### Mundo

Personagens, lugares, objetos, eventos etc.

### Pesquisa

Busca dentro de toda a obra.

Isso evita criar dezenas de menus.

# 5. Editor

Aqui está o coração do programa.

Eu faria algo deliberadamente próximo do Bloco de Notas.

### Por padrão:

* fonte confortável;
* largura de texto limitada;
* fundo limpo;
* sem barra de ferramentas;
* sem formatação pesada;
* sem menus ocupando espaço;
* salvamento automático.

### Atalhos

```text
Ctrl + N       Novo capítulo
Ctrl + S       Salvar
Ctrl + F       Pesquisar
Ctrl + Shift + F   Pesquisar no projeto
Ctrl + P       Modo foco
Ctrl + Z       Desfazer
```

E talvez:

**F11 → tela cheia**

# 6. Capítulos

A barra lateral seria essencialmente um navegador.

```text
CAPÍTULOS

01  O começo
02  A viagem
03  Curitiba
04  O encontro
05  A descoberta
06  —
07  A chuva

+ Novo capítulo
```

Cada capítulo poderia ter:

* título;
* número;
* status;
* palavras;
* data de criação/modificação;
* POV;
* personagens;
* localização;
* período temporal.

Mas **essas informações ficariam escondidas durante a escrita**.

Como você especificou, eu deixaria **somente três**:

### Claro

```text

```

### Escuro


Segue automaticamente Windows/Linux/macOS.

Sem:

* temas coloridos;
* temas "papel";
* temas personalizados;
* dezenas de opções.

Isso é coerente com a filosofia do produto.

# 18. O princípio arquitetural do TramaPad

Eu resumiria o projeto em três níveis:

```text
                         TRAMAPAD
                            │
             ┌──────────────┴──────────────┐
             │                             │
          ESCREVER                      ORGANIZAR
             │                             │
        ┌────┴────┐               ┌────────┼────────┐
        │         │               │        │        │
      Texto     Foco          Capítulos Personagens Notas
                                      │
                                  Lugares
                                      │
                                   Eventos
```

E existe uma regra importante:

> **Organização deve estar disponível, mas nunca exigir atenção.**

Isso, para mim, é o que diferencia o TramaPad de um simples editor de texto.

## O MVP que eu realmente construiria

Não começaria com tudo isso.

**Versão 0.1:**

1. Criar projeto
2. Abrir projeto
3. Criar capítulos
4. Editor de texto
5. Salvar automaticamente
6. Contagem de palavras
7. Pesquisa
8. Modo foco
9. Três temas
10. Exportar/importar Markdown

Depois:

**0.2 → personagens + lugares + notas**

**0.3 → metadados + relacionamentos + histórico**

**0.4 → corretor ortográfico**

**0.5 → linha do tempo + recursos mais inteligentes**

Isso permitiria que você tivesse um **TramaPad funcional relativamente cedo**, sem passar meses construindo funcionalidades antes de poder experimentar a experiência de escrita.

E há uma decisão que eu considero particularmente importante para o projeto: **o TramaPad deveria ser local-first**. O livro ficaria no computador do escritor, em arquivos que ele possa acessar diretamente, sem exigir conta, internet ou servidor. Sincronização em nuvem poderia vir posteriormente como recurso opcional.
